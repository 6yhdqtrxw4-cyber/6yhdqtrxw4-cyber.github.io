UUID / GUID Generator

Generate cryptographically random version 4 UUIDs in bulk, in the case and format you need.

What a UUID is

A UUID — universally unique identifier, called a GUID in Microsoft environments — is a 128-bit number written as 32 hexadecimal digits in five groups: f81d4fae-7dec-11d0-a765-00a0c91e6bf6. Those 32 digits give about 3.4 × 10³⁸ possible values, which is enough that generating one at random is effectively guaranteed to be unique without any central authority to check against.

That decentralisation is the whole point. Two systems that have never spoken to each other can each mint identifiers and never collide, which is why UUIDs are used for database primary keys, distributed tracing, and anything synced across devices without a coordinator.

Which version is this?

This tool generates version 4, the random variant. The version is encoded in the first character of the third group, and the variant in the first character of the fourth — so inspecting a UUID tells you how it was made:

  • v1 — based on the timestamp and the machine's MAC address. Sortable, but it leaks when and where it was made.
  • v4 — 122 bits of randomness, the rest being version and variant bits. What you want in almost every case.
  • v5 — a hash of a namespace plus a name, so the same input always gives the same UUID. Useful for deterministic ids.
  • v7 — a timestamp prefix followed by randomness. Newer, and popular for database keys because it sorts chronologically while staying unpredictable.

Why the randomness source matters

A predictable identifier is a security problem, not just a correctness one. If an attacker can guess the next id — because it comes from a counter, a timestamp, or Math.random() — then unguessable URLs stop being access control, and they can enumerate your records. This tool uses crypto.randomUUID(), or crypto.getRandomValues() where that is unavailable, both of which draw from the operating system's cryptographic generator.

Format variations you will meet

  • Standard — lowercase, with dashes. The RFC 4122 canonical form.
  • No dashes — 32 hexadecimal characters, used by some APIs and many database column types.
  • Braces — {...}, the .NET and Windows registry convention.
  • Uppercase — common in Oracle and in older Microsoft documentation.

These are all the same value. Case and punctuation are formatting, not data — which is why a system that compares UUIDs as case-sensitive strings is holding a bug.

FAQ

Can two generated UUIDs collide?

Mathematically yes, practically no. You would need to generate about 2.7 × 10¹⁸ v4 UUIDs before a 50% chance of any collision. For scale, generating a billion per second, that takes around 85 years.

Is a UUID safe to use as a secret?

No. Randomness makes it unguessable, but it is an identifier, not a credential — it is logged, indexed, cached and shared. Use a purpose-built token for secrets, and still enforce authorisation on the server.

Should I use a UUID as a database primary key?

It works, but randomly ordered keys hurt insert performance on clustered indexes because each new row lands in a random part of the index. If that matters, use UUID v7 or a ULID, which are time-ordered.

Does anything leave my browser?

No. Generation uses the Web Crypto API, which is local to the page.

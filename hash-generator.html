Hash Generator — SHA-256, SHA-384, SHA-512 and SHA-1

Generate a cryptographic hash of any text. Everything is computed locally with the browser’s own Web Crypto API.

What a hash is, and what it is for

A cryptographic hash function takes any amount of input and produces a fixed-length output — a fingerprint. SHA-256 always produces 64 hexadecimal characters, whether you feed it one letter or a gigabyte. Change a single character of the input and the output changes completely and unpredictably.

That combination — fixed size, one-way, and avalanche on any change — makes hashes useful for three things: verifying that a file or message arrived unchanged, comparing large values cheaply, and storing secrets so the original cannot be recovered.

Which algorithm to use

  • SHA-256 — the default choice, and what you want for checksums, signatures and content addressing. Part of the SHA-2 family.
  • SHA-384 / SHA-512 — longer variants of the same family. Slower, marginally stronger, required by some compliance rules. Useful when you want a hash that cannot be confused with a SHA-256 one.
  • SHA-1 — broken for security. Practical collision attacks were demonstrated in 2017. It is included here only because old systems and git still emit it; never use it for anything new.
  • MD5 — also broken, and not available through the browser's Web Crypto API at all, because providing it would encourage its use.

What hashing is not

A plain hash is not a way to store passwords. Because the same input always gives the same output, an attacker with a list of common passwords can precompute a lookup table in minutes. Password storage needs a deliberately slow, salted function — bcrypt, scrypt or Argon2 — not a fast hash like SHA-256. If you are building authentication, use a library designed for it.

Verifying a download

Paste the published checksum and the text together and this tool will split them apart, detect whether it is a 64-character (SHA-256) or 40-character (SHA-1) value, and tell you whether they match. For files, run the hash on your machine instead — sha256sum file on Linux, certutil -hashfile file SHA256 on Windows.

FAQ

Is my text sent to a server?

No. Hashing uses crypto.subtle.digest, which is built into the browser. This works with the network disconnected.

Can I hash a file here?

Not currently — this tool works on text. Hashing a large file in the browser is possible with File.stream() but needs an incremental digest implementation, which the Web Crypto API does not expose.

Can a hash be reversed?

No, not by design. There is no key and no inverse operation. The only practical attack is guessing the input and hashing it to compare — which is exactly why short or predictable inputs, like passwords, are unsafe to hash this way.

Why does hashing the same text twice give the same result?

That determinism is the point: it is what lets two parties compare fingerprints without exchanging the original data.

URL Encoder & Decoder

Percent-encode text for use in a URL, or decode a URL back to readable text. Choose the right mode for paths, query values or full URLs.

The two modes are not interchangeable

This is the mistake behind most broken links. encodeURIComponent escapes every character that has a reserved meaning in a URL, including / ? : @ & = + #. That is exactly right when you are encoding a value that will sit inside a query string. It is wrong when you are encoding a whole URL, because it destroys the separators that give the URL its structure.

So: encoding the search term shoes & socks should produce shoes%20%26%20socks. Encoding the URL https://example.com/a?b=1 should leave the ://, the / and the ? exactly as they are.

Which characters are reserved, and why

  • / ? # — structure: path, query, fragment.
  • & = — separate and assign query parameters.
  • + — the legacy form-encoding shorthand for a space.
  • % — the escape character itself, which is why a literal percent sign must be written as %25.
  • space — must be %20 in a URL. Browsers often display it back as a space, which hides the problem until the link is copied somewhere else.
  • " < > ` { } | \ ^ [ ] — unsafe or excluded, always encoded.

What double-encoding looks like

Encode an already-encoded string and the percent signs get encoded too: %20 becomes %2520, and a space reappears as the literal text "%20". If a decoded URL shows percent sequences that were not in your original text, it has been encoded twice somewhere along the way. The Decode button here reverses one layer at a time — press it again to strip a second layer.

FAQ

Why do some links use + for spaces and others %20?

+ comes from HTML form encoding (application/x-www-form-urlencoded) and is still what many servers expect in a query string. %20 is the general-purpose standard and the only correct choice in a path. The Form style option produces the + variant.

Can this encode a non-Latin URL?

Yes. The text is converted to UTF-8 bytes and each byte is percent-encoded, which is the correct behaviour for internationalised URLs. https://例え.jp/ページ becomes a fully escaped ASCII string.

Is the URL sent anywhere?

No. Encoding, decoding and the URL breakdown all use built-in browser APIs on this page.

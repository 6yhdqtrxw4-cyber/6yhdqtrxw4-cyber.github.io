What a Unix timestamp is

A Unix timestamp (also called epoch time or POSIX time) is the number of seconds that have elapsed since 00:00:00 UTC on 1 January 1970, not counting leap seconds. It is a single integer, it has no time zone, and it is the same everywhere on Earth at the same instant — which is exactly why it is used for storing times in databases and APIs.

The one thing to watch for is the unit. Most Unix systems use seconds; JavaScript, Java and many APIs use milliseconds. The two are easy to tell apart: a seconds timestamp for a date in this decade has 10 digits, and the same instant in milliseconds has 13.

Reading a timestamp by eye

  • 10 digits (e.g. 1790000000) — seconds, dates between 2001 and 2033.
  • 13 digits (e.g. 1790000000000) — milliseconds, the same range.
  • Negative — a date before 1970. Still valid, still meaningful.
  • 16+ digits — almost certainly nanoseconds or microseconds, from Go or some Python libraries.

Why the same timestamp shows different clock times

A timestamp has no time zone, but a formatted date does. This tool shows you all three views at once — ISO 8601 in UTC, the RFC-style UTC string, and the local time of your own machine — precisely because mixing them up is the most common date bug in software. A value that reads 14:05 for you may read 06:05 for a server in another region; the underlying number is identical.

The year 2038 problem

Systems that store a Unix timestamp in a signed 32-bit integer run out of room at 03:14:07 UTC on 19 January 2038. Values beyond that overflow into negative numbers and wrap around to 1901. Most modern systems use 64-bit integers and are unaffected, but embedded devices, older databases and legacy file formats still are.

FAQ

Is a timestamp in seconds or milliseconds?

Count the digits. Ten digits is almost certainly seconds; thirteen is milliseconds. The auto-detect option here uses that rule, and you can override it when a value is ambiguous.

Why does the timestamp not change when I change time zone?

Because it should not. The timestamp is an absolute instant. Only the human-readable rendering depends on the time zone, which is why the local line changes and the number does not.

What is ISO 8601?

An international standard for writing dates and times, for example 2026-09-30T14:05:00.000Z. The trailing Z means UTC. It is unambiguous, sorts correctly as plain text, and is the safest format to send between systems.

Does this work offline?

Yes. Conversions use the browser's own Date object, so nothing is sent anywhere.

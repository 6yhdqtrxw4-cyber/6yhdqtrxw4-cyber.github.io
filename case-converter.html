The eight cases, and when each one is correct

  • UPPER CASE — emphasis, acronyms, labels that must not be missed.
  • lower case — normalising text where casing is inconsistent.
  • Sentence case — the standard for body text, headings in most style guides, and UI copy.
  • Title Case — book and article titles. Short words such as of, the and and stay lowercase unless they come first.
  • camelCase — JavaScript and Java variables and functions.
  • PascalCase — class names, React components, C# methods.
  • snake_case — Python and Ruby identifiers, database columns.
  • kebab-case — URLs, CSS class names, HTML attributes.

Why the programming cases are harder than they look

Converting userProfileImageURL to snake_case requires knowing where the words begin. A naive split on capitals produces user_profile_image_u_r_l. This tool inserts a boundary between a lowercase letter and a following uppercase one, and treats runs of capitals followed by a lowercase letter as a single word — so URL stays together.

FAQ

Does Title Case follow a particular style guide?

It uses the common convention where articles, short prepositions and coordinating conjunctions stay lowercase unless they are the first or last word. Different publishers differ on the fine details.

Will it break my acronyms?

UPPER and lower obviously do not preserve them. For the programming cases, an existing acronym such as URL is kept as one word rather than split into letters.

Does it handle non-Latin scripts?

The letter-case conversions only apply where a script has case. Chinese, Japanese, Arabic and Hebrew have no upper or lower case, so those modes leave the text unchanged — the programming cases still work, since they operate on word boundaries.
